## 1. Overview

The repository has outgrown what a hand-maintained architecture section can describe. `AGENTS.md`
documents a layout (`src/frontend/<feature>/model/`, `src/backend/<feature>/services/`) that the
code does not have: as of the base commit there is **no `src/frontend/` directory at all**, no
feature contains a `model/` or `services/` subdirectory, and the only nested directory under
`src/backend/` is `src/backend/filemanagement/assets/`. Every agent that starts a change re-walks
the tree to answer "what modules exist and what do they expose", and the answer is never recorded.

This change adds a **generated map of the repository**: a stdlib-only generator
(`scripts/make_map.py`) that walks the tracked Python files with `ast` and writes a committed,
deterministic, human-readable `STRUCTURE.md` at the repository root — a directory tree plus a
per-package inventory of modules, classes, functions, methods and class fields, each with its
signature and docstring summary. The map is regenerated by a command, checked for freshness by a
`--check` mode wired into the local pre-commit hook, and read by agents before they walk the tree.
Because the map is generated from the code, it is by construction the truth about the current
layout; `AGENTS.md`'s *Project Structure* section is corrected to match it in the same PR.

### Goals

| ID | Goal |
|---|---|
| G-1 | One command produces a complete, deterministic map of the repository's Python layout, in under two seconds. |
| G-2 | The map is a committed artifact, and a local hook makes a stale map impossible to commit silently. |
| G-3 | An agent can answer "which modules exist, what do they expose, what is their signature" without walking the tree. |
| G-4 | The documented architecture (`AGENTS.md`) matches the real one, and stays matchable because the real one is now machine-readable. |

### Non-goals

- Not a documentation site, not a substitute for docstrings or `userdocs/` (the mkdocs site is unchanged).
- Not a dependency graph, call graph, coverage report or metrics dashboard — the map records structure, not relationships or quality.
- Not an architecture *enforcer*: it does not check boundaries or import rules (that is the review/verify phase's inspection, and `deptry`).

## 4. Definitions

| Term | Meaning |
|---|---|
| **file set** | The `.py` files the generator considers: `git ls-files --cached --others --exclude-standard` filtered to `*.py`, keeping only paths that exist on disk at run time. |
| **code dirs** | The top-level directories rendered in full in the tree: `src/`, `tests/`, `scripts/`, `migrations/`. |
| **package** | A directory containing an `__init__.py` (70 at the base commit: 11 under `src/`, 59 under `tests/`). A directory without one (e.g. `scripts/`, `migrations/`, `src/`, `tests/`) is grouped like a package but has no import name. |
| **module** | One `.py` file. |
| **public symbol** | A module-level or class-level class/function/method whose name does not start with `_`, plus every dunder (`__dunder__`) name, which is always public for the map. |
| **summary** | The normalized first logical line of a docstring (REQ-018). |
| **fresh render** | The exact bytes `scripts/make_map.py` would write for the current file set and options. |

## 5. Public Contract — the generator

### REQ-001 — Location and dependency budget
The generator is a single module at `scripts/make_map.py`, runnable as `uv run python scripts/make_map.py`.
It imports **only** the standard library (`ast`, `argparse`, `pathlib`, `subprocess`, `sys`, plus
`collections`/`re`/`dataclasses` as needed) and the standard typing surface. It adds no project
dependency and reads each source file **exactly once** (line count and AST from the same read).

### REQ-002 — CLI surface
The CLI accepts exactly these options; anything else is an argparse usage error (exit 2):

| Option | Default | Meaning |
|---|---|---|
| `--root PATH` | the repository root that contains `scripts/make_map.py`, resolved with `pathlib` | the directory the map describes |
| `--out PATH` | `STRUCTURE.md`, resolved **relative to the current working directory** | the map file to write or check |
| `--include-private` | off | also render `_name` functions, methods and classes |
| `--max-depth N` | `4` | tree rendering depth, counted in path segments from the root (`src`=1, `src/backend`=2, `src/backend/settings`=3, `src/backend/settings/registry.py`=4); must be ≥ 1 |
| `--check` | off | compare the existing `--out` file against a fresh render instead of writing |
| `-h`, `--help` | — | usage text listing every option above |

The generator never writes the `--root` path into the output; every path in the output is
`--root`-relative.

### REQ-003 — File set
The file set is `git ls-files --cached --others --exclude-standard` (index **plus** untracked-but-not-ignored
files), filtered to `*.py`, keeping only paths that exist on disk. A module created during
implementation therefore appears in the map before it is `git add`ed; a file deleted from the working
tree disappears from the map even while it is still in the index. When `--root` is not a git
repository (or `git` is unavailable), the generator falls back to a **built-in ignore list**
(`.git`, `.venv`, `__pycache__`, `.mypy_cache`, `.ruff_cache`, `.pytest_cache`, `data`, `dist`,
`build`, `.idea`) and does **not** parse `.gitignore` — a documented limitation, printed once to
stderr.

### REQ-004 — Exit-code contract

| Exit code | Meaning | Generate mode | `--check` mode |
|---|---|---|---|
| `0` | success | map written | existing file equals a fresh render after the REQ-005 newline normalisation |
| `1` | map is stale | not used | existing file differs from a fresh render |
| `2` | usage error (unknown/invalid option, `--max-depth < 1`) | argparse | argparse |
| `3` | map file missing | not used | `--out` does not exist |
| `4` | a source file could not be read or parsed | yes | yes |

The contract is fixed: no other exit code is produced, and `1`/`3` never occur in generate mode.

### REQ-005 — `--check` semantics
`--check` compares the **whole file** against a fresh render: the on-disk bytes are first normalised
`\r\n` → `\n`, then compared byte-for-byte (no other normalisation, no whitespace-insensitive diffing,
no section-level comparison). The single newline normalisation exists because the repository has no
`.gitattributes` and a `core.autocrlf=true` checkout presents the committed LF blob with CRLF on
Windows (EDGE-016); generate mode always writes LF. On a difference it prints exactly one line and
nothing else:

```text
STRUCTURE.md is out of date — run uv run python scripts/make_map.py
```

The line names the `--out` path as given (the default renders exactly the text above). No diff, no
counts, no per-section report. A missing `--out` file prints one line naming the missing path and
exits 3.

### REQ-006 — Unreadable or unparseable source is a hard failure
If a file in the file set cannot be parsed (`SyntaxError`), decoded (`UnicodeDecodeError`) or read
(`OSError`), the run **fails**: every offending path is reported (sorted, `--root`-relative, one per
line, with the exception type), nothing else is printed, **no output file is written**, and the exit
code is `4`. There is no degraded mode: the map is never partially generated, and a broken file is
never listed with a `(parse error)` marker.

### REQ-007 — Supported grammar
The supported Python grammar is the grammar of the **running interpreter** (`ast.parse` with no
`feature_version`). Today that is CPython 3.14, matching `[tool.mypy] python_version = "3.14"`. A file
using newer syntax is therefore an unparseable file under REQ-006 (EDGE-003) until the interpreter is
upgraded — the `feature_version` option is deliberately not exposed.

### REQ-008 — Document shape
The output is one UTF-8 Markdown document in this order and nothing else:

1. `# Repository structure`
2. one blank line, then the generated-by line `_Generated by \`scripts/make_map.py\`. Do not edit by hand._`
3. `## Directory tree` — REQ-009/REQ-010
4. `## Packages` — REQ-011…REQ-018

No timestamp, no generator version banner, no absolute path, no drive letter, no host or user name,
no "generated in N ms" line.

### REQ-009 — Directory tree content
The tree block lists, in this order:

1. every top-level **file** in the tracked set, by name, sorted;
2. every **code dir** (`src/`, `tests/`, `scripts/`, `migrations/`) rendered in full — one line per
   directory and one line per entry, sorted, indented two spaces per level, within `--max-depth`;
3. every other top-level **directory** as a single count line with a role label from a fixed built-in
   table, e.g. `docs/ — 200 files (process record)`, `.agents/ — 16 files (skills)`,
   `.github/ — 9 files (CI and tooling)`, `userdocs/ — 2 files (published docs)`. A directory with no
   entry in the table renders as `<name>/ — <N> files` with no label.

Counts are of tracked files under that directory (all file types, not only `.py`).

### REQ-010 — `--max-depth` prunes the tree only
`--max-depth` affects **only** the tree rendering. When entries exist below the limit, the deepest
rendered directory of that branch gets a final line `(+N dirs not shown)` (or `(+N files not shown)`
when only files are hidden; a branch with both renders one combined line
`(+N dirs, M files not shown)`). **Every** `.py` file in the file set is still parsed and, if it is in
the Packages scope (REQ-011), still listed there regardless of depth. Pruning can therefore never hide
a module from the map.

### REQ-011 — Packages section scope
The Packages section covers exactly:

- every module under `src/`, `scripts/` and `migrations/` (83 + 3 + 3 `.py` files at the base commit);
- every `tests/` module whose file name is `conftest.py` (17) or ends with `_test_helpers.py` (11).

No other `tests/` module gets a Packages entry (234 − 28 = 206 test modules appear in the tree only).
No module in scope is ever elided for size.

### REQ-012 — Group header and exports line
Modules are grouped by their containing directory, one group header per directory (32 groups at the
base commit: 27 packages, 5 plain directories). A **package** header shows its import name and its
`--root`-relative directory path:

```text
### `backend.settings` — src/backend/settings/
```

The import name is the directory path relative to the import root `src/` with `/` → `.`; for a package
outside `src/` it is the whole `--root`-relative path with `/` → `.` (e.g. `tests.acceptance.settings`).
A plain (non-package) directory header shows the path only, e.g. `### scripts/`. One header per
directory, never one per module.

A package whose `__init__.py` defines `__all__` renders one `exports:` line listing those names sorted;
otherwise it lists the public names it imports, sorted; a package `__init__.py` with neither renders no
`exports:` line (11 such lines at the base commit).

### REQ-013 — Module header and summary
Each module renders

```text
#### src/backend/settings/registry.py (412 lines)
```

followed by the module summary line (REQ-018) when the module has a docstring, and no summary line
when it does not (42 `tests/` modules and 1 `migrations/` module have none at the base commit).

### REQ-014 — Symbol inventory and signatures
Each module lists its symbols in **source order**: module-level classes, then module-level functions;
within a class, its annotated fields, then its methods. Rendering:

```text
- @logged_class class `SettingsRegistry`: Registers and validates settings.
  - `key: str`
  - `register(self, definition: SettingDefinition) -> None`: Register one definition.
- @logged def `register_settings`(registry: SettingsRegistry) -> None: Register the feature's settings.
```

- class line: `- ` + decorators (REQ-015) + `class ` + backticked ``Name(Base, ...)`` + `: ` + summary.
- module-level function line: `- ` + decorators + `def ` + backticked signature + `: ` + summary; an
  `async def` keeps the `async ` prefix inside the backticked signature.
- method line (two-space indent): `  - ` + decorators + backticked signature + `: ` + summary (no `def` keyword).
- signatures are produced with `ast.unparse` for parameters, annotations and return annotation, so
  formatting drift in the source cannot change the map; a parameter default is included **only when
  its unparsed text is ≤ 20 characters**.
- a nested class renders as a member line of its enclosing class (`  - class \`Inner\`: summary`) with
  its own members at the next indent level (12 nested classes exist at the base commit, all in `tests/`).
- module-level assignments, imports, `if TYPE_CHECKING` blocks and statements are not rendered.

### REQ-015 — Decorators
Every decorator on a rendered symbol is shown as a compact `@name` prefix, in source order, before the
`class`/`def`/signature token. Decorators are never skipped — `@logged`, `@logged_class`, `@property`,
`@staticmethod`, `@classmethod`, `@override` and `@pytest.fixture` all appear (216 decorators in `src/`).
A decorator that is not a plain name or attribute chain (a call, a subscript) renders as its
`ast.unparse` text.

### REQ-016 — Visibility rules
Dunder names (`__init__`, `__post_init__`, `__eq__`, …) are **always** rendered. `_name` functions,
methods and classes are hidden unless `--include-private` is passed (221 such symbols in the Packages
scope at the base commit). `--include-private` changes **only** which symbols are rendered: module and
package inclusion is unaffected, and no `_name` module is ever hidden or added by the flag.

### REQ-017 — Class fields
A class-level annotated assignment renders as one line `  - \`name: annotation\`` — **no default value
and no `Field(...)` payload**. Fields are rendered in source order, capped at **15 per class**; when a
class has more, a final line `  - … +N fields` reports the elided count (exactly 1 class exceeds the
cap at the base commit: `src/backend/settings/models.py`, 17 fields). Unannotated class-level
assignments are not rendered.

### REQ-018 — Summary normalization
A summary is the **first logical line** of the docstring with runs of whitespace collapsed to single
spaces, backticks removed, and truncated to **100 characters** with a trailing `…` marker when longer.
A symbol or module with no docstring renders **no summary** and no trailing `:`. An empty docstring is
"no docstring".

### REQ-019 — Determinism
Two runs over an unchanged tree produce **byte-identical** output. Therefore: files and directories are
sorted by `--root`-relative POSIX path; symbols keep source order; the encoding is UTF-8; newlines are
LF; there is **no trailing whitespace** on any line; the file ends with **exactly one** newline. The
output therefore passes the active `trailing-whitespace` and `end-of-file-fixer` pre-commit hooks
unchanged.

### REQ-020 — Path form
Every path in the output is `--root`-relative and rendered with `as_posix()` — forward slashes on
Windows and Linux alike — so the same map is produced on a Windows workstation and on `ubuntu-latest`
CI.

## 6. Public Contract — the committed artifact and its integration

### REQ-021 — `STRUCTURE.md` is a committed, generated artifact
`STRUCTURE.md` is committed at the repository root, is produced only by running the generator, and is
never hand-edited. Its content is the fresh render for the commit it is recorded at.

### REQ-022 — The skill
`.agents/skills/code-structure-map/SKILL.md` exists, follows the skill format (`name` + `description`
frontmatter, body under **60 lines**), and states exactly four rules: read `STRUCTURE.md` before
walking the tree; regenerate when it is stale (`uv run python scripts/make_map.py`); regenerate in the
**same commit** as the `.py` change; on a merge conflict in `STRUCTURE.md`, take either side and
regenerate — never hand-merge the generated file.

### REQ-023 — Local hook, no CI job
`.pre-commit-config.yaml` gains one **local** hook in the existing `repo: local` block:

```yaml
- id: structure-map-check
  name: structure map is up to date
  entry: uv run python scripts/make_map.py --check
  language: system
  pass_filenames: false
  stages: [pre-commit]
  files: \.py$
```

It is **check-only** (it never rewrites the map) and it is the only freshness gate. No GitHub Actions
workflow runs `make_map.py --check`.

### REQ-024 — `AGENTS.md` corrected to the real layout
`AGENTS.md` is updated in exactly four places, and nowhere else:

1. **Project Structure** — the fenced layout block and the sentences around it are rewritten to the
   layout the map shows: flat feature packages under `src/backend/<feature>/` (no `model/`, no
   `services/` subdirectory anywhere; the only nested `src/` directory is
   `src/backend/filemanagement/assets/`), **no `src/frontend/` directory exists** (the coverage config
   reserves the name), `tests/<category>/<feature>/`, plus `scripts/`, `migrations/`, `userdocs/` and
   `.agents/skills/`. Every literal directory path shown in the corrected block exists in the generated
   map.
2. **Tooling & Execution Environment** — one line pointing at the map and the skill: what it is, the
   generate command, the `--check` command, and the same-commit regeneration rule.
3. **Tooling & Execution Environment**, the type-check line — `uv run mypy scripts/` is added next to
   `uv run mypy src/`.
4. **Skill-to-Phase Mapping** — an `(ambient)` row for `code-structure-map` (optional, before
   exploring), and `python-best-practices` is given the same `(ambient)` marking so the table covers
   every non-phase skill.

The stale `tests/architecture/` citations are already gone from live guidance (merged
`chore/architecture-tests-missing`); this change verifies that none is reintroduced.

### REQ-025 — `scripts/` joins the type gate
`uv run mypy scripts/` is added to the `type-check` job of `.github/workflows/quality.yml` (next to
`uv run mypy src/`), and the pre-existing error in `scripts/` is fixed so the widened gate is clean at
merge time. Measured at the base commit: **one** error —
`scripts/verify_spec.py:74: error: Item "TextIO" of "TextIO | Any" has no attribute "reconfigure"  [union-attr]`
(3 source files checked). The fix is confined to that file and must not change its behaviour.

### REQ-026 — The map hook is advisory, never a gate
Nothing in the workflow makes reading or generating the map a prerequisite or a pass/fail criterion:
no phase gate, no handoff field, no prohibition depends on it. `.agents/skills/specify/SKILL.md` P.1
gains **one** advisory sentence to the effect of "if `STRUCTURE.md` exists, read it before walking the
tree". The hook of REQ-023 is a local commit guard, not a workflow gate.

### REQ-027 — Freshness policy is documented where agents read it
The regeneration rule (regenerate in the same commit as the `.py` change) and the conflict rule (take
either side and regenerate, never hand-merge) appear in the skill (REQ-022) **and** in the `AGENTS.md`
pointer line (REQ-024).

## 12. Traceability

`scripts/check_traceability.py` requires a matrix row for every `REQ-XXX`/`AC-XXX` defined in
`docs/specs/`. This spec defines **REQ-001…REQ-027** and **AC-001…AC-027** (54 rows; AC-001…AC-027 map
1:1 onto REQ-001…REQ-027 in §7). Phase 3 adds the rows with `RED` status and the derived test names;
Phase 5 replaces them with GREEN evidence in the *Structure Map Matrix* section of
`docs/verification/traceability.md`. `INV`/`EDGE`/`NFR` rows are not required by the checker and are
added where they carry a distinct witness.

Spec coverage is 100% when every REQ-001…REQ-027 and AC-001…AC-027 has a GREEN test in §11's files.

**The checker cannot police these rows.** `check_traceability.py` treats `REQ-XXX`/`AC-XXX` as one global namespace,
and all 54 IDs above are already defined by other specs in `docs/specs/`, so its "every REQ/AC has a matrix row" rule
is satisfied by other changes' rows and passes with no *Structure Map* row present. The rows are therefore a
**workflow obligation, not a CI-enforced gate** — Phase 3 and Phase 5 must add them, and a checker PASS is not
evidence of this spec's coverage (see `docs/verification/structure-map.md`, finding 2).

## 13. Design notes (non-normative)

- **Why `ast` and not a documentation tool:** the map must be deterministic, dependency-free and
  grammar-exact. `ast` + `ast.unparse` gives canonical signatures immune to source formatting drift,
  and keeps `deptry` clean (Q-29).
- **Why the map is the truth and `AGENTS.md` follows:** a hand-written architecture section drifts
  (it currently describes directories that do not exist). Generating the map and correcting the prose
  in the same PR makes the two agree at a point in time and keeps them agreeable, because the map is
  machine-checkable afterwards (Q-11).
- **Why parse errors are fatal:** a silently skipped file makes the map lie about completeness, which
  is the exact failure this change exists to prevent (Q-26b).
- **Why the hook is local and advisory:** a CI job for `--check` would fail other changes' PRs on
  unrelated staleness, and a workflow gate would collide with the in-flight `value-triage-gate` change
  that rewrites the Phase P table (Q-6, Q-13).
- **Coverage:** `[tool.coverage.run] source = ["src/backend", "src/frontend"]`, so `scripts/` and its
  tests earn no coverage credit and the `fail_under = 92` floor must not move; this change touches no
  coverage configuration.
- **Why `--check` normalises newlines instead of adding `.gitattributes`:** this repository has no
  `.gitattributes` and `core.autocrlf=true` on the development host, so a checked-out text file shows
  CRLF while the blob is LF. Normalising one comparison in `--check` is a two-line change inside the
  generator; a repo-wide `*.md text eol=lf` rule would change every Markdown file's checkout on Windows
  and is out of scope (EDGE-016).
- **Known ceiling (ponytail):** the tree walk is a single `O(files)` pass with one read per file and no
  caching; the naive role-label table is a literal dict. Both are fine at 570 tracked files; the upgrade
  path if the repository grows 10× is a per-file mtime cache and a config-driven label table.
